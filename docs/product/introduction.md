# 什么是异步慢任务服务 (ASTS)

异步慢任务服务（Asynchronous Slow Task Service，ASTS）是面向业务系统的**分布式异步任务处理平台**，专门承接耗时较长（>10 秒）的业务逻辑——例如大数据量导出、视频转码、报表生成、批量数据处理——让业务接口立即返回，任务在后台异步执行，并通过细粒度进度、可靠回调与可视化管理台贯穿任务全生命周期。

## 核心功能

| 功能 | 说明 |
|------|------|
| 异步任务提交 | 业务方提交任务后立刻拿到任务 ID，耗时逻辑与业务接口解耦 |
| 实时进度反馈 | Worker 按步骤上报进度（每步独立进度 + 权重计算全局进度，0-100%） |
| 任务取消 | `PENDING`/`RUNNING` 任务可发起取消，`CANCELLING` → `CANCELLED` 两段式确认 |
| 失败重试 | 按任务类型的 `maxRetries` 自动重试；租约过期由系统回收重新派发 |
| 可靠回调 (Webhook) | 任务终态经 Outbox 模式投递到业务回调地址，最多 8 次指数退避 |
| 回调防伪造 | 回调携带 HMAC-SHA256 签名三头，密钥为租户密钥，接收方可验签 |
| 多租户隔离 | 租户级凭据、数据隔离（`tenant_id` 全链路过滤 + PG RLS 兜底）、租户级 Worker |
| 背压与限流 | 任务类型级并发上限/队列上限准入；接口按租户维度滑动窗口限流 |
| 嵌入组件 | 三种开箱即用的前端组件（任务列表/详情/卡片），短期 token 免密嵌入 |
| 可视化管理台 | 任务管理、租户管理、类型配置、Worker 监控、统计概览、归档查询 |

## 产品优势

- **接入成本低**：一个提交接口 + 一个轮询接口即可完成接入；提供 Java 示例模块 `lotask4j-demo`。
- **执行可靠**：Fencing Token + 版本号双保险，杜绝多 Worker 重复执行与跨租户篡改；租约过期自动回收。
- **回调必达**：Outbox 模式 + 指数退避重试（8 次），任务终态不丢；签名头防第三方伪造退款等敏感受体。
- **多租户安全**：凭据一次下发、AES-256-GCM 落库；密钥轮换支持 24 小时双版本宽限并可一键撤销存量会话。
- **可观测**：执行事件审计（append-only）、Micrometer 指标（`lotask4j.*`）、统计概览与管理台可视化。

## 使用限制

| 项 | 限制 | 说明 |
|----|------|------|
| 任务执行时长 | 建议在 10 秒以上、小时级以内 | 超长任务请自行分段提交 |
| 任务有效期 | 默认 7 天，可按类型配置 `timeoutSeconds` | 超时任务由 TaskReaper 回收 |
| Outbox 重试 | 最多 8 次（指数退避，上限 1 小时） | 超限标记 `FAILED`，不再投递 |
| 密钥宽限期 | 24 小时双版本 | 旧密钥宽限期内仍可换 Token |
| 登录防爆破 | 5 次失败锁定 15 分钟 | 按 client_id 维度 |
| 同租户会话 | 单会话互斥 | 同租户新换 Token 会踢掉旧 Token |
| Webhook 事件 | 仅任务终态（`SUCCESS`/`FAILED`/`CANCELLED`） | 配置了 `callbackUrl` 才投递 |
