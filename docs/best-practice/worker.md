# Worker 开发规范

## 拓扑与隔离

- Worker 按租户部署，只消费本租户任务（服务端强制，轮询 SQL 带租户过滤）。
- 一种 Worker 进程建议只消费一种任务类型（`taskType` 固定），独立伸缩。
- 多实例并发轮询安全（`SKIP LOCKED`），无需分布式锁。

## 抢占与凭据管理

1. 抢到任务后**立即持久化** `executionToken` 与 `version`（进程重启场景需可恢复）；
2. 每次上报成功后任务 `version` 会 +1，使用响应/本地递增后的最新值；
3. 上报收到 `20409` 时：任务已被回收或取消——**立即停止业务动作**，重新进入轮询。

## 执行规范

| 规范 | 说明 |
|------|------|
| 幂等消费 | 重试语义意味着同任务可能被执行多于一次（前次实例崩溃）。业务写入用"按任务 ID 去重"或 upsert |
| 分步上报 | 长任务拆步骤，每步完成即上报（既是进度展示，也是**租约续约**） |
| 协作式取消 | 分片/批循环内检查取消：上报进度收到 `20409` 且任务处于 `CANCELLING` 时收尾上报 `CANCELLED` |
| 失败携带归因 | `FAILED` 必带 `lastErrorCode`（枚举化，如 `OSS_TIMEOUT`）与 `lastErrorMessage` |
| 大结果瘦身 | `result` 走对象存储存文件、库里放引用；避免大 JSON 拖慢查询 |
| 资源隔离 | 执行线程池与业务接口线程池隔离；单任务异常必须捕获，不允许拖垮 Worker 进程 |

## 心跳与优雅退出

- 轮询行为本身就是心跳（服务端按租户+IP+类型 upsert 节点表），保持轮询间隔 ≤ 30 秒即显示在线；
- 优雅停机：收到 SIGTERM 后停止领取新任务，把手头任务收尾（上报终态或让其自然过期重派），再退出；
- 崩溃兜底：租约过期后任务自动回 `PENDING` 重派（未达 maxRetries 时），无需人工介入。

## 轮询节奏

| 参数 | 建议 |
|------|------|
| 轮询间隔 | 空闲 3-5 秒；可用退避策略（连续空轮询逐步拉长至 30 秒） |
| 单实例并发 | 按任务类型 `concurrencyLimit` 配置；Worker 本地并发 ≤ 配置值 |
| 超时预算 | 单步执行时长不要超过租约时长（默认配置见任务类型 `timeoutSeconds`） |
