# 应用场景

## 数据导出

业务后台的"导出明细"是最典型场景：数据量大、耗时长，同步接口必然超时。

1. 业务方提交 `data_export` 任务，`payload` 携带查询条件与导出目标。
2. Worker 分批拉取数据写入目标（文件/OSS），按批次上报进度。
3. 完成后 Worker 上报 `SUCCESS`，`result` 返回文件地址。
4. 若提交时配置了 `callbackUrl`，业务系统收到签名 Webhook 后通知用户下载。

## 视频转码 / 媒体处理

上传完成后触发 `video_transcode` 任务，Worker 依托 FFmpeg 等工具转码。转码天然多步骤，可配合任务类型的**步骤定义**（`stepsConfig`，如 解析 → 转码 → 封装）按权重自动计算全局进度，前端嵌入"任务卡片"组件实时展示。

## 批量数据处理

商品价格批量调整、会员权益批量发放等运营动作：提交批量任务后运营人员可在管理台观察整体进度；发生异常时通过 `CANCEL` 中止，避免错误扩大。

## 定时报表生成

上游调度系统（如 XXL-Job）在固定时间提交报表生成任务，`callbackUrl` 指向报表分发服务——任务完成即自动推送，无需人工轮询。

## 面向多业务方的平台化输出

ASTS 为多租户设计：每个业务方（租户）使用独立凭据接入，数据相互隔离，各自维护自己的任务类型配置与 Worker 池。平台运营通过管理台统一治理租户生命周期与配额。
