# 任务归档

## 归档策略

| 项 | 值 |
|----|-----|
| 执行时间 | 每日 02:00（`TaskArchiver`，顺带预建当月+下月分区） |
| 归档范围 | 终态（`SUCCESS`/`FAILED`/`CANCELLED`）且完成时间 ≥ 7 天前 |
| 归档方式 | 逻辑删除：`is_deleted = 1`，**物理数据保留** |
| 排除对象 | `PENDING` / `RUNNING` 任务永不归档 |

## 前端可见性

| 视图 | 数据范围 | 能力 |
|------|----------|------|
| 当前任务 | `is_deleted = 0` | 查看 / 取消 / 重派等全部操作 |
| 归档任务 | `is_deleted = 1` | **只读**查询：详情、步骤、结果、事件时间线 |

## 分区与容量

- `asts_task` 按月 RANGE 分区，每日归档任务顺带保障当月与下月分区存在（无 default 滞留时直接 CREATE，有滞留行走承接表 copy→delete→ATTACH）。
- 归档不释放物理空间；如需清理历史数据请按分区 DROP（DBA 操作），先确认合规要求。

## 常见问题

**归档后 Webhook 还会投递吗？**
归档只改变列表可见性，不影响已完成任务的投递状态。Outbox 投递独立于归档。

**归档任务还能查详情吗？**
可以。管理台归档页与 `Admin API` 均可按 ID 查询归档任务（只读）。
